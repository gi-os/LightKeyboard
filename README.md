A clone of the Light Phone 3's built-in keyboard, for any app — with swipe typing and a
bundled-dictionary autocorrect.

> A fork of [adam-weber/light-keyboard](https://github.com/adam-weber/light-keyboard). The keyboard
> looks exactly the same; typing and autocorrect underneath it are new.

**Current release: v1.0.21** (tag `v1.0.21`). `applicationId` is `app.lightphonekeyboard`.

## Why this exists

On a stock Light Phone, the black-and-white keyboard lives only inside Light's own tools — every
other app gets the ordinary Android system keyboard, and there is no Light one to choose. This is a
faithful recreation, packaged as a real system keyboard you can set as the default, so every app on a
modified Light Phone shares the same look.

Upstream's autocorrect called Android's `SpellCheckerSession`. That does nothing on LightOS, because
there is no Google spell-check service installed to answer it — corrections silently never arrive.
So this fork bundles its own dictionary (`res/raw/words.bin`, ~63k words, generated by
[`tools/gen_dict.py`](tools/gen_dict.py)) and both autocorrect and swipe typing run against it,
entirely on-device. Nothing here ever touches the network.

A word list on its own only knows how common a word is, which is why a keyboard built on one suggests
things nobody would write: "happy bir" offers *birth*, "went wro" offers *wrote*, "how mu" offers
*music*. Since v1.0.9 there is a second bundled file, `res/raw/bigrams.bin` — 180,000 word pairs with
how much more often each pair occurs than chance would explain — and the suggestion strip, autocorrect
and swipe typing all use it to reorder what they were already going to offer. It is a lookup table, not
a language model: it sees one word back, it can only move a candidate a few places, and it can never
remove the word your spelling most obviously matches.

## Quick start

**With [Obtainium](https://github.com/ImranR98/Obtainium)** (recommended — keeps you updated):

1. Install Obtainium.
2. Add an app, and give it this repository: `https://github.com/gi-os/LightKeyboard`
3. It installs the latest release and tells you when a new one ships.

**Or by hand**: grab the APK from [Releases](../../releases) and open it.

**Turn it on** — Light Keyboard's own setup screen has both steps:

1. **Enable Light Keyboard** — opens Android's keyboard settings, where you switch it on.
2. **Choose it as your keyboard** — makes it the active input method.

That's it — under five minutes, most of it Android's own settings UI.

## Configuration

Optional settings, all in the app itself:

- **Autocorrect** (on by default) — fixes misspellings when you finish a word, using the bundled
  dictionary. Backspace once to undo a correction. Off types exactly what you tap.
- **Swipe typing** (on by default) — drag from letter to letter to write a whole word, then lift.
  Guessed wrong? Backspace cycles through the other words your trace could have meant.
- **Suggestions** (off by default) — a thin strip above the keys showing three words: completions of
  what you're typing, the correction autocorrect has in mind, or alternate swipe readings, ranked
  against the word before them. Tap one to use it. **Hold** one to forget it — the keyboard stops
  offering that word, from the bundled dictionary as well as your own list. The leftmost slot is the
  *keep-as-typed* slot (iOS-style): shown in quotes, tapping it commits your literal spelling and learns
  the word. It shows up whenever the word can't grow any further — including the moment after you finish
  an unknown word, and after autocorrect has replaced one, where tapping it puts your spelling back.
  Off by default because the LightOS keyboard has no suggestion bar of its own, and turning this on
  makes the keyboard one strip taller everywhere.
- **My words** — names and anything else the dictionary has never seen. Adding a word stops it being
  autocorrected into something else, makes it something autocorrect can arrive *at*, and makes it
  traceable by swipe. Without it, "Bjorn" becomes "born" every time. Anything you've forgotten from the
  suggestion strip is listed under the same screen, with a ✕ to put it back.
- **Auto-Capitalize** / **Auto-Period** (both on by default) — capitalize sentence starts; double-tap
  space for a period.
- **Return key** / **Emoji keyboard** (both on by default) — show or hide those keys.
- **Voice dictation** (off by default) — downloads a ~40 MB offline speech-to-text model (Vosk) once,
  then a mic key lets you speak instead of type, on-device. A **Delete model** link appears once
  downloaded, to reclaim the space.
- **Compact keyboard** (off by default) — shorter keys, tighter spacing.
- **Keyboard layout** — QWERTY, AZERTY, or QWERTZ.

Layout and appearance changes take effect the next time the keyboard opens.

## Build it yourself

```sh
./gradlew :app:assembleDebug      # debug build
./gradlew :app:assembleRelease    # release build (unsigned unless signing env vars are set)
```

Needs JDK 17 and the Android SDK (API 35). Every push is built and tested by
[`.github/workflows/build.yml`](.github/workflows/build.yml).

The two bundled data files are generated, not hand-written — see [`tools/`](tools/README.md):

- `res/raw/charmodel.bin` — character trigram model for per-tap key selection
  ([`tools/gen_charmodel.py`](tools/gen_charmodel.py))
- `res/raw/words.bin` — the word list behind autocorrect and swipe typing
  ([`tools/gen_dict.py`](tools/gen_dict.py))
- `res/raw/bigrams.bin` — the word-pair table that ranks candidates against the preceding word
  ([`tools/gen_bigrams.py`](tools/gen_bigrams.py))

The typing logic lives in `app/src/main/java/app/lightphonekeyboard/text/` — dictionary, autocorrect,
swipe decoding, prefix completion, personal word list — and deliberately has **no Android
dependencies**, so it is unit-tested against the real dictionary rather than only on a phone.

### Signing

The signing key is a repo secret (`KEYSTORE_BASE64`), never a file in the repository. Only its
certificate fingerprint is committed, in `signing-fingerprint.txt`, and CI fails if a build's
certificate doesn't match it — Android identifies an app by `(packageName, certificate)`, so a changed
certificate silently breaks every existing install's ability to upgrade, surfacing only as
`Failure: Invalid` at install time. Release builds are never left unsigned: the Gradle build fails
outright with no key rather than producing an APK that looks fine and then refuses to install.

To build a signed APK yourself, either set `KEYSTORE_FILE`, `KEYSTORE_PASSWORD`, `KEY_ALIAS` and
`KEY_PASSWORD`, or drop a `keystore.properties` in the project root:

```properties
storeFile=/path/to/your.jks
storePassword=…
keyAlias=…
keyPassword=…
```

Debug builds share that key and the same `applicationId` (no `.debug` suffix), so `adb install -r`
replaces an installed release in place rather than leaving a second Light Keyboard in the input-method
list. Coming from the upstream app, or from a build made before this key existed: Android refuses the
update because the certificate differs — uninstall the old one first.

## Contributing

- The weights in `Corrector.kt` and `GestureDecoder.kt` were fitted against the benchmarks in
  `app/src/test`. If you change them, run `./gradlew :app:test` and look at what you traded away —
  these tests exist precisely so tuning isn't done by ear.
- Every key-unit coordinate in the typing/gesture code is measured from the top of the first key row,
  not the view, so the suggestion strip's height doesn't shift gesture math.
- `bigrams.bin` holds no word list at all — its key is a 32-bit FNV-1a hash of `left \0 right`, computed
  independently in `tools/gen_bigrams.py` and in `ContextModel.fingerprint`. If those two ever drift
  apart, every lookup returns 0, context ranking silently switches itself off and *nothing else fails*.
  `ContextModelTest` asserts known-good pairs out of the shipped file precisely to catch that.
- Verifying a release APK without an Android SDK: AGP renames resource paths in release builds
  (`res/raw/words.bin` ships as something like `res/x5.bin`), so grepping the zip for a filename proves
  nothing — match on size + SHA-256 instead. The APK is v2/v3-signed only (no `META-INF/*.RSA`); check
  for the `APK Sig Block 42` magic located from the EOCD central-directory offset instead.
- PRs against typing/dictionary logic should include or update a JUnit test in `app/src/test` — that
  suite is what lets this be tuned without an Android device.

## Version history

Every push to `main` builds, tests, and publishes a signed APK as the next `v1.0.<n>` release (`n` is
the CI run number) — see [`.github/workflows/build.yml`](.github/workflows/build.yml). Obtainium picks
it up on its own. A push can bundle more than one commit; only the push's final commit carries the tag.

- **v1.0.21** (2026-08-01) — **Swiping i-m gives "I'm", not "jim"; swipe-down-to-close needs a hold
  first.** "im" was reachable in the dictionary but scored on its own entry, which
  tools/gen_dict.py deliberately floors at -13.0 for chat shorthand nobody actually types — read as
  "I'm" it isn't nearly that rare, so the floor lost every time to "jim"/"kim", whose paths the same
  trace also fits. Scored instead at a constant standing in for what "I'm" is actually worth, checked
  against the shipped dictionary and grid before shipping rather than guessed. Separately: dismiss now
  waits for the finger to sit still before a downward swipe counts, so a fast trace that happens to
  start moving down (tracing "no" or "on") no longer races the close gesture and loses depending on
  touch-sample timing.
- **v1.0.19** (2026-08-01) — Reverted an in-progress attempt at swipeable contractions that didn't
  land cleanly (see v1.0.21 above for the version that did).
- **v1.0.16** (2026-08-01) — The two-letter allowlist brought back in step with what the tests
  actually pin, plus "hi".
- **v1.0.13** (2026-07-31) — **The commonest two-letter words are pinned by a test.** "to", "it", "is"
  and "my" already decoded first after v1.0.11 — measured across twenty seeds, three trace speeds and
  the bare two-point flick the view reports for a quick stroke, every one of them wins outright. But the
  two-letter test measured a *rate* (22 of 26 first, all 26 reachable), and a rate would still pass with
  any single word broken, so those four now have their own assertion. No ranking change: nothing needed
  fixing. The count in the older test's comment was one high, and the fourth word that loses on
  frequency ("ah" to "an") was unnamed; both corrected.

- **v1.0.11** (2026-07-31) — **Two-letter words can be swiped.** "of", "to", "in", "is", "it" and "on"
  are all in the twenty commonest words in English, and none of them could be swiped at all: the
  decoder's dictionary scan began at three letters, so a stroke from *o* to *f* came out "off", *t* to
  *o* came out "top", *b* to *y* came out "buy". Between neighbouring keys it was worse — "we", "as",
  "ok" produced nothing whatsoever, because the whole stroke was shorter than the path length the
  decoder needed before it would treat a drag as a gesture, and the first letter had already been
  retracted by then. Two-letter words are now scored like any other, with two things keeping them
  honest: a stroke that begins and ends on the same key is still a tap (a drifted tap can never become a
  word), and a two-letter reading has to beat the field by a margin rather than tie it, because its
  ideal path is a straight line and a straight line fits almost anything. Scoring also gained a length
  term — a candidate is charged for distance the finger travelled that its own path can't account for,
  which is what tells "here" from "he" — and the trace now records where the finger lifted, so a quick
  flick between two keys isn't thrown away for having reported too few points. Single taps are untouched:
  "a" and "I" are still typed, never swiped.
- **v1.0.9** (2026-07-31) — **Suggestions ranked against the sentence, and a strip you can edit.**
  Three things:
  - A bundled word-pair table (`res/raw/bigrams.bin`, 180,000 pairs) reorders the candidates the strip,
    autocorrect and swipe typing already produced, using how much more often each pair occurs than
    chance. "happy bir" now offers *birthday* over *birth*, "went wro" *wrong* over *wrote*, "how mu"
    *much* over *music*. Reranking is bounded: a candidate climbs one place per two nats of pair
    strength, at most three places, and the candidate your spelling most obviously matches can never be
    pushed out of the strip. Autocorrect gets a far tighter bound again (1.2 places), because it commits
    without asking. Sentence starts have no pair to rank on and are left exactly as they were. If the
    table is missing or corrupt, ranking falls back to the old behaviour rather than failing.
  - Keeping the word you actually typed is always reachable. The keep-as-typed slot used to be
    suppressed while the dictionary could still extend what you'd typed, which meant a name that is also
    the start of an ordinary word (Wil, Kai, Cass, Ravi) never got a slot at all. It now appears for a
    deliberate mid-sentence capital, for a word you've just finished, and for a word autocorrect has
    already replaced — where tapping it puts your spelling back *and* learns it.
  - **Hold** a suggestion to forget it. Removed from your own list and added to a forgotten list that
    the bundled dictionary is filtered against too, so a word the corpus keeps pushing at you can
    actually be got rid of. It stays a correctly spelled word — typing it deliberately is still left
    alone — and the "My words" screen lists what you've forgotten with a ✕ to restore it.

  Costs about 955 KB of APK (the pair table, deflated), taking the download from 9.7 MB to 10.6 MB. A
  pair lookup measures ~10 ns and the whole reranking pass adds ~12 µs to a keystroke — next to nothing
  beside the dictionary scan that produced the candidates, and no measurable change to autocorrect at
  all (1.36 ms before, 1.37 ms after).
- **v1.0.6** (2026-07-29) — Suggestion strip's keep-as-typed slot, iOS style; suppressed while the
  typed prefix still has completions, so typing "keyboard" doesn't first offer to add "k", "ke", "key".
- **v1.0.4** (2026-07-29) — Three-slot suggestion strip (off by default) and the "My words" personal
  dictionary.
- **v1.0.3** (2026-07-29) — Swipe typing, bundled-dictionary autocorrect, Return key moved to the
  corner; CI switched to publishing a signed APK on every push to `main`.
- **v0.1.5** (2026-06-07) — Numbers layer stays active across field restarts; open keyboard settings
  from the system input-method settings screen.
- **v0.1.4** (2026-06-01) — Adjustable keyboard height, in-settings keyboard tester, cleaner
  swipe-to-dismiss; numbers layer opens automatically for number/phone/date fields; APK version derived
  from the release tag so Obtainium stops showing phantom updates.
- **v0.1.3** (2026-05-31) — Keyboard layouts (QWERTY/AZERTY/QWERTZ), compact mode, adaptive typing
  settings; scrollbar adjusted to match LightOS exactly.
- **v0.1.2** (2026-05-31) — LightOS-style line-based toggles, replacing Material switches.
- **v0.1.1** (2026-05-31) — Fixed a VOSK (voice dictation) minification bug.
- **v0.1.0** (2026-05-31) — Initial fork of adam-weber/light-keyboard.
