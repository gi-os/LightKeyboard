A clone of the Light Phone 3's built-in keyboard, for any app — with swipe typing and a
bundled-dictionary autocorrect.

> A fork of [adam-weber/light-keyboard](https://github.com/adam-weber/light-keyboard). The keyboard
> looks exactly the same; typing and autocorrect underneath it are new.

**Current release: v1.0.6** (tag `v1.0.6`). `applicationId` is `app.lightphonekeyboard`.

## Why this exists

On a stock Light Phone, the black-and-white keyboard lives only inside Light's own tools — every
other app gets the ordinary Android system keyboard, and there is no Light one to choose. This is a
faithful recreation, packaged as a real system keyboard you can set as the default, so every app on a
modified Light Phone shares the same look.

Upstream's autocorrect called Android's `SpellCheckerSession`. That does nothing on LightOS, because
there is no Google spell-check service installed to answer it — corrections silently never arrive.
So this fork bundles its own dictionary (`res/raw/words.bin`, ~63k words, generated by
[`tools/gen_dict.py`](tools/gen_dict.py)) and both autocorrect and swipe typing run against it,
entirely on-device. Nothing here ever touches the network.

## Quick start

**With [Obtainium](https://github.com/ImranR98/Obtainium)** (recommended — keeps you updated):

1. Install Obtainium.
2. Add an app, and give it this repository: `https://github.com/gi-os/LightKeyboard`
3. It installs the latest release and tells you when a new one ships.

**Or by hand**: grab the APK from [Releases](../../releases) and open it.

**Turn it on** — Light Keyboard's own setup screen has both steps:

1. **Enable Light Keyboard** — opens Android's keyboard settings, where you switch it on.
2. **Choose it as your keyboard** — makes it the active input method.

That's it — under five minutes, most of it Android's own settings UI.

## Configuration

Optional settings, all in the app itself:

- **Autocorrect** (on by default) — fixes misspellings when you finish a word, using the bundled
  dictionary. Backspace once to undo a correction. Off types exactly what you tap.
- **Swipe typing** (on by default) — drag from letter to letter to write a whole word, then lift.
  Guessed wrong? Backspace cycles through the other words your trace could have meant.
- **Suggestions** (off by default) — a thin strip above the keys showing three words: completions of
  what you're typing, the correction autocorrect has in mind, or alternate swipe readings. Tap one to
  use it. The leftmost slot is the *keep-as-typed* slot (iOS-style): shown in quotes, tapping it commits
  your literal spelling and learns the word. Off by default because the LightOS keyboard has no
  suggestion bar of its own, and turning this on makes the keyboard one strip taller everywhere.
- **My words** — names and anything else the dictionary has never seen. Adding a word stops it being
  autocorrected into something else, makes it something autocorrect can arrive *at*, and makes it
  traceable by swipe. Without it, "Bjorn" becomes "born" every time.
- **Auto-Capitalize** / **Auto-Period** (both on by default) — capitalize sentence starts; double-tap
  space for a period.
- **Return key** / **Emoji keyboard** (both on by default) — show or hide those keys.
- **Voice dictation** (off by default) — downloads a ~40 MB offline speech-to-text model (Vosk) once,
  then a mic key lets you speak instead of type, on-device. A **Delete model** link appears once
  downloaded, to reclaim the space.
- **Compact keyboard** (off by default) — shorter keys, tighter spacing.
- **Keyboard layout** — QWERTY, AZERTY, or QWERTZ.

Layout and appearance changes take effect the next time the keyboard opens.

## Build it yourself

```sh
./gradlew :app:assembleDebug      # debug build
./gradlew :app:assembleRelease    # release build (unsigned unless signing env vars are set)
```

Needs JDK 17 and the Android SDK (API 35). Every push is built and tested by
[`.github/workflows/build.yml`](.github/workflows/build.yml).

The two bundled data files are generated, not hand-written — see [`tools/`](tools/README.md):

- `res/raw/charmodel.bin` — character trigram model for per-tap key selection
  ([`tools/gen_charmodel.py`](tools/gen_charmodel.py))
- `res/raw/words.bin` — the word list behind autocorrect and swipe typing
  ([`tools/gen_dict.py`](tools/gen_dict.py))

The typing logic lives in `app/src/main/java/app/lightphonekeyboard/text/` — dictionary, autocorrect,
swipe decoding, prefix completion, personal word list — and deliberately has **no Android
dependencies**, so it is unit-tested against the real dictionary rather than only on a phone.

### Signing

The signing key is a repo secret (`KEYSTORE_BASE64`), never a file in the repository. Only its
certificate fingerprint is committed, in `signing-fingerprint.txt`, and CI fails if a build's
certificate doesn't match it — Android identifies an app by `(packageName, certificate)`, so a changed
certificate silently breaks every existing install's ability to upgrade, surfacing only as
`Failure: Invalid` at install time. Release builds are never left unsigned: the Gradle build fails
outright with no key rather than producing an APK that looks fine and then refuses to install.

To build a signed APK yourself, either set `KEYSTORE_FILE`, `KEYSTORE_PASSWORD`, `KEY_ALIAS` and
`KEY_PASSWORD`, or drop a `keystore.properties` in the project root:

```properties
storeFile=/path/to/your.jks
storePassword=…
keyAlias=…
keyPassword=…
```

Debug builds share that key and the same `applicationId` (no `.debug` suffix), so `adb install -r`
replaces an installed release in place rather than leaving a second Light Keyboard in the input-method
list. Coming from the upstream app, or from a build made before this key existed: Android refuses the
update because the certificate differs — uninstall the old one first.

## Contributing

- The weights in `Corrector.kt` and `GestureDecoder.kt` were fitted against the benchmarks in
  `app/src/test`. If you change them, run `./gradlew :app:test` and look at what you traded away —
  these tests exist precisely so tuning isn't done by ear.
- Every key-unit coordinate in the typing/gesture code is measured from the top of the first key row,
  not the view, so the suggestion strip's height doesn't shift gesture math.
- Verifying a release APK without an Android SDK: AGP renames resource paths in release builds
  (`res/raw/words.bin` ships as something like `res/x5.bin`), so grepping the zip for a filename proves
  nothing — match on size + SHA-256 instead. The APK is v2/v3-signed only (no `META-INF/*.RSA`); check
  for the `APK Sig Block 42` magic located from the EOCD central-directory offset instead.
- PRs against typing/dictionary logic should include or update a JUnit test in `app/src/test` — that
  suite is what lets this be tuned without an Android device.

## Version history

Every push to `main` builds, tests, and publishes a signed APK as the next `v1.0.<n>` release (`n` is
the CI run number) — see [`.github/workflows/build.yml`](.github/workflows/build.yml). Obtainium picks
it up on its own. A push can bundle more than one commit; only the push's final commit carries the tag.

- **v1.0.6** (2026-07-29) — Suggestion strip's keep-as-typed slot, iOS style; suppressed while the
  typed prefix still has completions, so typing "keyboard" doesn't first offer to add "k", "ke", "key".
- **v1.0.4** (2026-07-29) — Three-slot suggestion strip (off by default) and the "My words" personal
  dictionary.
- **v1.0.3** (2026-07-29) — Swipe typing, bundled-dictionary autocorrect, Return key moved to the
  corner; CI switched to publishing a signed APK on every push to `main`.
- **v0.1.5** (2026-06-07) — Numbers layer stays active across field restarts; open keyboard settings
  from the system input-method settings screen.
- **v0.1.4** (2026-06-01) — Adjustable keyboard height, in-settings keyboard tester, cleaner
  swipe-to-dismiss; numbers layer opens automatically for number/phone/date fields; APK version derived
  from the release tag so Obtainium stops showing phantom updates.
- **v0.1.3** (2026-05-31) — Keyboard layouts (QWERTY/AZERTY/QWERTZ), compact mode, adaptive typing
  settings; scrollbar adjusted to match LightOS exactly.
- **v0.1.2** (2026-05-31) — LightOS-style line-based toggles, replacing Material switches.
- **v0.1.1** (2026-05-31) — Fixed a VOSK (voice dictation) minification bug.
- **v0.1.0** (2026-05-31) — Initial fork of adam-weber/light-keyboard.
